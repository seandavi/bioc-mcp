# Spec #2: Scaffold — Worker, MCP + REST transports, capability registry, envelope, CI

Issue: [seandavi/bioc-mcp#2](https://github.com/seandavi/bioc-mcp/issues/2).
Project design: [proposal-mcp.qmd](https://github.com/seandavi/bioc-infrastructure/blob/spec/mcp/proposal-mcp.qmd).
Conventions: [AGENTS.md](../../AGENTS.md).

Every package API named below was checked on 2026-10-22 against the published package (types and
docs) and exercised in a throwaway prototype: in-process MCP client calls, `/mcp/:toolset`
routing, the Host allowlist, REST query coercion, the OpenAPI 3.1 document, `tsc` with
TypeScript 7, `vitest run` and the SDK docs' `curl` against `wrangler dev`. Notes marked
**Verified** record behaviour the implementer must account for.

## Goal

A deployable-but-not-deployed Cloudflare Worker that every later issue builds on:

- a **capability registry**: one capability = name, module, title, description, zod input and
  data schemas, and `handler(input, deps)` with injected `fetch`, cache, clock and env;
- **two thin transports** over it: MCP at `/mcp` and `/mcp/:toolset`, REST at
  `GET /api/v1/<module>/<capability>` with an OpenAPI 3.1 document at `/api/openapi.json`;
- the **result envelope** `{ data, summary, sources }` with an 8 KB size guard;
- an **upstream helper** (fetch with timeout, cache with per-upstream TTL, typed errors);
- the **`bioc://about` resource** and `GET /api/v1/about`;
- one trivial capability, `meta_ping`, kept as the health check;
- CI that runs typecheck and tests, and the AGENTS.md "Commands" section.

## Non-goals

- No `docs`, `pkg` or `ops` capabilities (issues #3–#10). No real upstream adapter, so no recorded
  real-upstream fixtures; the upstream helper is tested against a synthetic `example` upstream.
- No deploy, rate limiting, usage logging or metrics (#11). No `wrangler deploy` in CI.
- No MCP prompts (#4, #10). No CORS headers on the REST API.
- No GitHub token use. The `GITHUB_TOKEN` binding is typed and passed through `deps.env` only.
- No pagination helper (`cursor`); it arrives with the first list-returning tool.
- No `@cloudflare/vitest-pool-workers`. **Verified:** 0.23.0 peers on `vitest ^4.1`, while
  current vitest is 5.0.5. Tests run in Node with injected deps; the Workers-only code is the
  five-line entry in `src/index.ts` and `createCloudflareCache`, which is tested against a fake
  `Cache`.

### `src/errors.ts`

```ts
export type ErrorCode =
  | 'invalid_input'      // REST 400
  | 'not_found'          // REST 404
  | 'upstream_error'     // REST 502: upstream unreachable, non-2xx other than 404, or unparseable
  | 'upstream_timeout'   // REST 502
  | 'result_too_large'   // REST 500: a capability bug; the size guard caught it
  | 'internal';          // REST 500

export class CapabilityError extends Error {
  readonly code: ErrorCode;
  readonly details: { upstream?: string; url?: string; status?: number };
  constructor(code: ErrorCode, message: string, details?: CapabilityError['details']);
}

export function httpStatusFor(code: ErrorCode): 400 | 404 | 500 | 502;

// REST error body, also used for the 404 on unknown toolsets and unknown routes.
export const ErrorBodySchema = z.object({
  error: z.object({ code: z.string(), message: z.string() }).catchall(z.unknown()),
});
```

Messages are written for an agent to act on: they say what failed and what to try instead.
Messages never include request arguments beyond the identifiers the caller sent.

### `src/envelope.ts`

```ts
export const SourceSchema = z.object({
  url: z.string().describe('Public URL the data came from'),
  as_of: z.string().describe("ISO 8601 date or date-time: the upstream's own data timestamp when it publishes one, else its Last-Modified, else when this server fetched it"),
});
export type Source = z.infer<typeof SourceSchema>;

export function envelopeSchema<D extends z.ZodType>(data: D) {
  return z.object({
    data,
    summary: z.string().describe('One or two sentences answering the question; the MCP text content'),
    sources: z.array(SourceSchema).describe('Provenance: every upstream URL used, with freshness'),
  });
}
export interface Envelope<T> { data: T; summary: string; sources: Source[] }

export const MAX_RESULT_BYTES = 8192;
/** UTF-8 byte length of JSON.stringify(envelope). */
export function envelopeBytes(envelope: Envelope<unknown>): number;
/**
 * Throws CapabilityError('result_too_large', `${tool} returned ${n} bytes; the limit is 8192. If the
 * tool takes a limit or filter, narrow the request; otherwise this is a server bug, please report
 * it at https://github.com/seandavi/bioc-mcp/issues.`).
 */
export function assertEnvelopeSize(envelope: Envelope<unknown>, tool: string): void;
```

Measure with `new TextEncoder().encode(JSON.stringify(envelope)).length`. The guard rejects; it
never truncates (structured data cannot be cut generically). Capabilities keep results small
themselves (excerpts, limits, cursors).

### `src/upstreams/cache.ts`

```ts
export interface CachedUpstream {
  url: string;
  body: string;
  contentType: string | null;
  lastModified: string | null;   // ISO 8601, parsed from the Last-Modified header
  fetchedAt: string;             // ISO 8601, from deps.now()
}
export interface UpstreamCache {
  get(url: string): Promise<CachedUpstream | undefined>;
  put(url: string, value: CachedUpstream, ttlSeconds: number): Promise<void>;
}
/** Map-backed; an entry expires when now() >= stored-at + ttlSeconds. For tests and Node. */
export function createMemoryCache(now: () => Date): UpstreamCache;
/** Cloudflare Cache API adapter (the Worker passes caches.default). */
export function createCloudflareCache(cache: Pick<Cache, 'match' | 'put'>): UpstreamCache;
```

`createCloudflareCache`: the key is the upstream URL string. `put` stores
`new Response(body, { headers })` with `content-type`, `cache-control: public, max-age=<ttl>`,
`x-bioc-mcp-fetched-at` and, when present, `x-bioc-mcp-last-modified`; `get` rebuilds
`CachedUpstream` from a match. Both methods catch and swallow cache exceptions (a broken cache is
a miss, never an error).

### `src/upstreams/http.ts`

```ts
export interface Upstream {
  id: string;            // stable, kebab-case, e.g. 'registry', 'r-universe'
  name: string;          // human name used in messages, e.g. 'Bioconductor registry'
  baseUrl: string;       // https:, no credentials, ends with '/', no query/fragment
  ttlSeconds: number;    // positive integer; cache TTL for 200 responses
  timeoutMs?: number;    // positive; default DEFAULT_TIMEOUT_MS
  description: string;   // one line for bioc://about
}
export const DEFAULT_TIMEOUT_MS = 10_000;
export const USER_AGENT = `bioc-mcp/${VERSION} (+https://github.com/seandavi/bioc-mcp)`;

export interface UpstreamResponse extends CachedUpstream { fromCache: boolean }

/**
 * Encode one caller-supplied value as a single URL path segment.
 *
 * Every adapter must build upstream paths through this helper (`items/${pathSegment(id)}.json`),
 * never by interpolating raw input. It rejects values that could climb out of the segment:
 * '', '.', '..', and anything containing '/', '\\' or an encoded dot or slash (%2e, %2f).
 */
export function pathSegment(value: string): string;

/**
 * The SSRF guard below is only sound for an https: baseUrl that ends with '/' and has no query or
 * fragment. The baseUrl must not carry credentials. No message ever includes the baseUrl itself, so a
 * password in a malformed or non-https: URL never reaches a client. ttlSeconds must be a positive integer (about and cache-control take
 * integers) and timeoutMs, when set, positive and finite. Checked at registration
 * (validateRegistry) and again on every fetch, so an adapter cannot bypass it by passing an
 * upstream it never registered.
 */
export function assertUpstream(upstream: Upstream): void;

/** GET `path` relative to upstream.baseUrl, through the cache. */
export function fetchUpstream(deps: Deps, upstream: Upstream, path: string): Promise<UpstreamResponse>;
/** fetchUpstream + JSON.parse; bad JSON → CapabilityError('upstream_error'). */
export function fetchUpstreamJson(deps: Deps, upstream: Upstream, path: string):
  Promise<{ response: UpstreamResponse; json: unknown }>;
/** Provenance for one response: as_of = asOf ?? response.lastModified ?? response.fetchedAt. */
export function sourceFor(response: UpstreamResponse, asOf?: string): Source;
```

`fetchUpstream` behaviour, in order:

1. `assertUpstream(upstream)`; a failure → `CapabilityError('internal', …)` (the rules are listed
   under `validateRegistry`; no message includes the baseUrl, so a password never reaches a client). Then
   `const url = new URL(path, upstream.baseUrl)`. If `url.origin` differs from the base's origin
   or `url.pathname` does not start with the base's pathname, throw
   `CapabilityError('internal', …)`. This is the SSRF guard: no capability can fetch outside a
   registered upstream. Adapters build every path through `pathSegment()` for each
   caller-supplied value; it rejects `''`, `.`, `..`, `/`, `\`, `%2e` and `%2f`, and
   percent-encodes the rest.
2. `deps.cache.get(url.href)`; a hit returns `{ ...hit, fromCache: true }`.
3. `deps.fetch(new Request(target, { headers: { 'user-agent': USER_AGENT }, redirect: 'manual', signal }))`
   with `signal = AbortSignal.timeout(upstream.timeoutMs ?? DEFAULT_TIMEOUT_MS)`. A
   301/302/303/307/308 with a `Location` is resolved against the current target, released
   (`response.body?.cancel()`) and re-checked against the base origin and path (outside →
   `upstream_error` "…redirected outside its base URL"). At most 3 redirects are followed; a 4th
   → `upstream_error` "…redirected more than 3 times". A 3xx without `Location` is an ordinary
   non-2xx.
4. Errors, with `<url>` the requested URL (`url.href`, also `details.url`) and `RETRY` the literal
   `Try again shortly.`:

   | Case | Code | Message |
   |---|---|---|
   | fetch rejects, `name` is `TimeoutError` or `AbortError` | `upstream_timeout` | `<name> did not answer within <ms> ms (<url>). Try again shortly.` |
   | fetch rejects, other | `upstream_error` | `Could not reach <name> (<url>). Try again shortly.` |
   | status 404 | `not_found` | `<name> has nothing at <url>` |
   | status ≥ 500 | `upstream_error` | `<name> returned HTTP <status> (<url>). Try again shortly.` |
   | other non-2xx | `upstream_error` | `<name> returned HTTP <status>` |
   | `response.text()` rejects, timeout | `upstream_timeout` | same as the fetch timeout row |
   | `response.text()` rejects, other | `upstream_error` | `Could not read the response from <name> (<url>). Try again shortly.` |

   Capabilities may catch the 404 and rephrase it. `details.status` is set for the status rows.
5. Read the body as text; build the `CachedUpstream`; `deps.cache.put(…, upstream.ttlSeconds)`
   only for status 200; return with `fromCache: false`. The cache key and `url` stay the
   requested URL, not a redirect target.

### `src/core/registry.ts`

```ts
export interface Capability<I extends z.ZodObject = z.ZodObject, D extends z.ZodType = z.ZodType> {
  module: string;                       // /^[a-z]+$/
  name: string;                         // `${module}_<verb_or_noun>`, /^[a-z]+_[a-z][a-z0-9_]*$/
  title: string;                        // short human title; MCP `title`, OpenAPI `summary`
  description: string;                  // what it answers; which tool to use instead
  input: I;                             // flat, REST-carriable, and accepts its own output (see validateRegistry)
  data: D;                              // schema of envelope.data
  output: ReturnType<typeof envelopeSchema<D>>;   // = envelopeSchema(data), set by defineCapability
  // Method syntax on purpose: bivariant parameters let Capability<Specific> sit in Capability[].
  handler(input: z.output<I>, deps: Deps): Promise<Envelope<z.output<D>>>;
}
export function defineCapability<I extends z.ZodObject, D extends z.ZodType>(
  spec: Omit<Capability<I, D>, 'output'>,
): Capability<I, D>;

export interface Module {
  name: string;                 // /^[a-z]+$/; also the toolset path segment
  description: string;
  upstreams: Upstream[];        // every upstream its capabilities call; listed by bioc://about
  capabilities: Capability[];
}

/** Production registry. Later issues append their modules here. */
export const modules: readonly Module[] = [metaModule];

/** Throws Error with a specific message on the first violation. createApp calls it. */
export function validateRegistry(modules: readonly Module[]): void;

/** `/api/v1/<module>/<name without "<module>_">`, e.g. meta_ping → /api/v1/meta/ping. */
export function restPath(capability: Capability): string;
```

`validateRegistry` rejects: a module name not matching `/^[a-z]+$/`; duplicate module names; a
capability whose `module` differs from its containing module, whose name does not match the
pattern or start with `<module>_`, or whose `description` is empty; duplicate capability names;
two upstreams with the same `id` but different fields (compared field by field with
`sameUpstream`, so key order does not matter); an upstream that fails `assertUpstream` (`https:`,
no credentials, trailing `/`, no query or fragment, positive-integer `ttlSeconds`, positive
finite `timeoutMs`); any input field that the REST transport cannot carry; and any input field
whose schema does not accept its own output. For the REST check, compute
`z.toJSONSchema(capability.input, { io: 'input' })`; every property must have `type` in
`string | number | integer | boolean`, or `type: 'array'` whose `items.type` is one of those.
(Enums are `type: 'string'` and pass; nullable fields and unions produce `anyOf` and fail.)

**Idempotent input.** MCP parses input twice: the SDK validates the arguments and hands the
parsed value to our callback, then `invokeCapability` parses it again. REST parses once. A
`.transform()`, or a `.pipe()` to another type, would pass on REST and fail on MCP, so a
capability's input schema must accept its own output; transform in the handler instead. For each
field, `z.toJSONSchema(field, { io: 'output' })` must not throw ("has a transform") and must equal
`io: 'input'` apart from `default` ("parses to a different type than it accepts"); `.prefault()`
sets `default` on the input side only. `.default()`, `.catch()`, `.trim()`, `.toLowerCase()` and
`z.coerce.number()` pass; `.transform()`, `.pipe(z.coerce.number())` on a string and
`z.stringbool()` fail. The check compares JSON Schemas, so it cannot see value-rewriting
`.overwrite(fn)` or `z.preprocess(fn, …)`; those must be idempotent by construction.

### `src/core/invoke.ts`

```ts
export type InvokeResult<T = unknown> =
  | { ok: true; envelope: Envelope<T> }
  | { ok: false; error: CapabilityError };

export async function invokeCapability(
  capability: Capability, rawInput: unknown, deps: Deps,
): Promise<InvokeResult>;
```

Steps: `capability.input.safeParse(rawInput)`; failure → `invalid_input` with
`z.prettifyError(result.error)`. Run the handler; a thrown `CapabilityError` passes through; any
other throw is logged with `console.error(capability.name, error)` and becomes
`internal` (`"<name> failed unexpectedly"`). Then `assertEnvelopeSize`. Then
`capability.output.safeParse(envelope)`; failure is logged and becomes `internal`
(`"<name> produced output that does not match its schema"`). Both transports call only this
function to run a capability; neither contains capability logic.

`createMcpApp`:

```ts
const app = createMcpHonoApp({
  host: '0.0.0.0',                      // not localhost: the allowlists below apply instead
  allowedHosts: config.allowedHosts,
  allowedOrigins: config.allowedOrigins,
```

Keep one `createMcpHandler(() => buildMcpServer(modules, selected, deps), { maxRequestBodySize: 65_536, onerror: (e) => console.error('mcp', e) })`
per normalized toolset key (`selected.map(m => m.name).join('+')`) in a `Map` inside the
closure; the factory itself runs per request, as the SDK requires. Leave `legacy` at its default
(`'stateless'`): 2025-era clients, and the docs' `curl`, are served by that path (**Verified**).
Routes:

- `app.all('/', (c: Context) => handlerFor(all).fetch(c.req.raw, { parsedBody: c.get('parsedBody') }))`
- `app.all('/:toolset', …)`: `parseToolset`; on failure return 404 with
  `{ error: { code: 'unknown_module', message: 'Unknown module(s): nope. Valid modules: meta, example. Use /mcp for every module, or /mcp/<module>[+<module>…].', unknown: ['nope'], valid: ['meta', 'example'] } }`.

Annotate the handler parameter as `c: Context` (SDK docs tip: otherwise `c.get('parsedBody')`
does not compile).

`buildMcpServer`:

```ts

    title: capability.title,
    description: capability.description,

    outputSchema: capability.output,
    annotations: { readOnlyHint: true, destructiveHint: false, idempotentHint: true },
  },
  // The SDK validates args against inputSchema before this callback runs. Its failures come back
  // as isError text "Input validation error: Invalid arguments for tool <name>: …", not
  // "invalid_input: …"; REST reports the same failure as 400 invalid_input.
  async (args: Record<string, unknown>) => {
    const result = await invokeCapability(capability, args, deps);
    return result.ok
      ? { content: [{ type: 'text', text: result.envelope.summary }], structuredContent: result.envelope }
      : { content: [{ type: 'text', text: `${result.error.code}: ${result.error.message}` }], isError: true };
```

The SDK validates arguments against `inputSchema` and `structuredContent` against `outputSchema`
(**Verified**). Input failures come back as `isError` text
`Input validation error: Invalid arguments for tool <name>: <details>` (for example
`… example_item: id: Invalid string: must match pattern /^[a-z0-9-]+$/`), not `invalid_input: …`;
REST reports the same failure as 400 `invalid_input`. We keep the SDK's wording, because dropping
`inputSchema` would drop it from `tools/list`. The text content is the summary only,
as the issue specifies.

### `src/transports/rest.ts`

```ts
export interface RestAppOptions { modules: readonly Module[]; deps: Deps }
/** OpenAPIHono with full paths: /api/v1/<module>/<cap>, /api/v1/about, /api/openapi.json. */
export function createRestApp(options: RestAppOptions): OpenAPIHono;
/** Query string → input object, typed by the input's JSON Schema. */
export function queryToInput(input: z.ZodObject, params: URLSearchParams): Record<string, unknown>;
```

With the local helper
`const json = <S extends z.ZodType>(schema: S, description: string) => ({ description, content: { 'application/json': { schema } } })`,
for each capability:

1. `const route = createRoute({ method: 'get', path: restPath(capability), operationId: capability.name, tags: [capability.module], summary: capability.title, description: capability.description, request: { query: capability.input }, responses: { 200: json(capability.output, 'The result envelope (same as MCP structuredContent)'), 400: json(ErrorBodySchema, 'Invalid input'), 404: json(ErrorBodySchema, 'Not found upstream'), 500: json(ErrorBodySchema, 'Server error'), 502: json(ErrorBodySchema, 'Upstream failed or timed out') } })`.
2. `api.openAPIRegistry.registerPath(route)` — documents the route without attaching
   zod-openapi's query validator.
3. `api.get(restPath(capability), handler)` where the handler runs
   `invokeCapability(capability, queryToInput(capability.input, new URL(c.req.url).searchParams), deps)`
   and returns `c.json(envelope, 200)` or `c.json({ error: { code, message } }, httpStatusFor(code))`.

**Verified:** binding `request.query` through `app.openapi()` rejects `limit=3` ("expected
number, received string"), because query values are strings. `registerPath` plus our own
coercion keeps the OpenAPI parameters exactly as the input schema declares them (`integer`,
`boolean`, `default`, `minimum`) and validates with the same schema MCP uses.

`queryToInput` computes `z.toJSONSchema(input, { io: 'input' }).properties` (cache it per
schema in a `WeakMap`). For each property with at least one value in `params`: `integer` /
`number` → `Number(v)` (an empty string stays `''` so validation reports it); `boolean` →
`'true'`/`'false'` to booleans, anything else unchanged; `array` → `params.getAll(name)` with
each item coerced by `items.type`; otherwise the last value as a string. Unknown query
parameters are ignored.

Also:

- `GET /api/v1/about` → `c.json(buildAbout(modules), 200)`, registered the same way with
  `AboutSchema` as the 200 response.
- `api.doc31('/api/openapi.json', { openapi: '3.1.0', info: { title: 'Bioconductor MCP REST API', version: VERSION, description: 'Read-only REST mirror of the bioc-mcp tools. Unstable until v1.' }, tags: modules.map((module) => ({ name: module.name, description: module.description })) })`
  (one tag per module, registry order; each capability route uses its module name as its tag).

```ts
import { parseConfig, type AppConfig } from './config';

export function createApp(options: { config: AppConfig; deps: Deps; modules?: readonly Module[] }): Hono {
  const modules = options.modules ?? registryModules;
  validateRegistry(modules);
  const app = new Hono();
  app.route('/mcp', createMcpApp({ modules, deps: options.deps, config: options.config }));
  app.route('/', createRestApp({ modules, deps: options.deps }));
  app.notFound((c) => c.json({ error: { code: 'not_found', message: `No route for ${c.req.method} ${new URL(c.req.url).pathname}. MCP: /mcp. REST: /api/v1 (OpenAPI at /api/openapi.json).` } }, 404));
  app.onError((error, c) => { console.error(error); return c.json({ error: { code: 'internal', message: 'Internal error' } }, 500); });
  return app;
}

interface WorkerEnv extends Env { GITHUB_TOKEN?: string }   // Env from worker-configuration.d.ts
let app: Hono | undefined;
export default {
  fetch(request, env, ctx) {
    app ??= createApp({
      config: parseConfig(env),
      deps: {
        fetch: (r) => fetch(r),          // wrapper: never store the bare global fetch on an object
        cache: createCloudflareCache(caches.default),
        now: () => new Date(),
        env: { GITHUB_TOKEN: env.GITHUB_TOKEN },
      },
    });
    return app.fetch(request, env, ctx);
  },
} satisfies ExportedHandler<WorkerEnv>;
```

The app is built on the first request because bindings arrive with the request. Host/Origin
validation applies to `/mcp*` only: the REST API is plain public GETs, and an Origin check there
would block browser callers for no gain.

### Test support

- `fixtureFetch(routes: Record<string, FixtureRoute>): FetchFn & { calls: string[] }` where
  `FixtureRoute = { file: string; status?: number; headers?: Record<string, string> } | { status: number; body?: string; headers?: Record<string, string> } | 'timeout' | 'network-error'`.
  `file` is relative to `test/fixtures/` and read with `readFileSync(new URL('../fixtures/' + file, import.meta.url), 'utf8')`.
  `'timeout'` returns a promise that rejects with the request signal's `reason` when it aborts;
  `'network-error'` rejects with `new TypeError('fetch failed')`. An unrouted URL rejects with
  `Error('Unexpected upstream request: <url>')`. Every requested URL is pushed to `calls`.
- `makeTestApp(options?: { routes?: Record<string, FixtureRoute>; now?: () => Date }) → { app, fetch, cache }`:
  `createApp({ config: { allowedHosts: ['test.local'], allowedOrigins: ['test.local'] }, modules: [metaModule, exampleModule], deps })`
  with `createMemoryCache(now)` and `env: {}`.
- `appFetch(app)`: a `(url, init) => Promise<Response>` that builds the `Request` and **sets the
  `host` header from the URL** before calling `app.fetch`. **Verified:** `new Request()` in Node
  (and Hono's `app.request()`) sends no Host header, and the allowlist then answers 403
  "Missing Host header".
- `connectClient(app, path)`: `new Client({ name: 'test', version: '0' }, { versionNegotiation: { mode: 'auto' } })`
  connected over `new StreamableHTTPClientTransport(new URL('http://test.local' + path), { fetch: appFetch(app) })`.
  Tests close the client in `afterEach`.

## Risks

- **Cache API on `workers.dev`.** Cloudflare documents functional cache operations for custom
  domains; on `*.workers.dev` they may be no-ops. Then every call goes upstream, which is
  harmless for `meta_ping` but matters for the 8 MB registry index (#6). Check after the first
  deploy (#11); the cache seam (`UpstreamCache`) lets #6 add an in-isolate memory layer without
  touching capabilities.
- **Clients that ignore `structuredContent`** see only the summary text. The issue specifies
  summary-only text; client behaviour is checked in #12.
- **Young dependencies.** SDK v2 (2.3.x), TypeScript 7 and Vitest 5 are recent. All were
  exercised together in the prototype; if TypeScript 7 misbehaves in CI, `typescript@^6.0.3`
  is the fallback, with the same `tsconfig.json`.
- **`exactOptionalPropertyTypes`** can make SDK option objects awkward (write `{ a: x }` only
  when `x` is defined). It compiled in the prototype; keep it.
- **`localhost` in the production Host allowlist** is deliberate (one config for dev and prod)
  and harmless on a public Worker; #11 can split dev and prod vars if wanted.
- **REST path naming** (`/api/v1/meta/ping`, the tool name without its module prefix) is set
  here; the REST API is unstable until v1, so a later change costs little.
